# ReconcileAI · 财务对账助手

[English documentation](README.en.md)。界面默认英文，右下角可切换中文；报告标题跟随所选语言，原始交易内容保留原文。英文模板已放在 `dist/examples/`。

**A local-first financial reconciliation prototype combining deterministic matching, an NLP candidate ranker, and human review.**

上传公司账本和银行流水，自动匹配明确一致的交易，推荐摘要不同的候选，标记重复与异常，再导出报告。免费、无需账号、无需 API 密钥。

![对账工作台](docs/screenshot.png)

## 不会编程也能运行

1. 下载完整项目并解压。
2. 双击 `打开对账助手.bat`，或打开 `dist/index.html`。
3. 点击 **体验虚构示例**。不需要安装任何程序。
4. 在待复核列表中确认、排除候选；已匹配项可以撤销。
5. 点击 **导出对账报告**，用 Excel 打开下载的 CSV。

示例 Excel 在 `dist/examples/` 中；页面也提供下载入口。所有名称与交易都是虚构的。

## 功能

- XLSX / CSV 导入；选择工作表、标题行和字段列。
- 支持单列带符号金额，或分列收入 / 支出；可显式反转方向。
- 明确匹配：同币种、相同金额、日期窗口内唯一编号一致；或同日规范化摘要完全一致。双方候选必须唯一，重复项和编号冲突不自动匹配。
- NLP 逻辑回归模型为模糊候选排序；只推荐，不自动确认。
- 显示日期差、金额差、编号冲突、疑似重复和无对应项。
- 人工确认 / 排除 / 撤销；一笔流水不能重复使用。
- 按币种汇总有效源数据净额；不把候选当成已匹配，不把金额差异自动抹平。
- 导出完整有效记录覆盖的 CSV；无效行另行导出，保留来源行号。

## AI 的具体实现

无需联网的机器学习基线，实现在 `dist/model.js`。不是大语言模型，也不是预训练语义嵌入。

1. 中文与英文文本规范化；提取字符特征。
2. 仅在训练集上拟合字符二元组 TF-IDF。
3. 每对摘要生成 7 个特征：截距、TF-IDF 余弦相似度、字符与二元组 Jaccard 重合、包含关系、长度比和数字冲突。
4. 在 68 个合成标注文本对上，以固定初始化、梯度下降、L2 正则训练逻辑回归。
5. 16 个独立编写的合成文本对作为固定留出测试集；所有失败结果公开保留。

对账时先限制同币种、同收支方向、日期窗口和可配置金额差异，再用文本模型评分。排名结合文本、日期、金额和编号冲突。最高三个候选展示给人工；排名分数不是校准后的正确概率。

## 真实计算的评估结果

| 检查 | 结果 | 解释 |
|---|---:|---|
| 文本测试准确率 | 56.25% | 9/16，包含相似公司名称与不同措辞的难例 |
| 文本 Precision | 0.545 | 6 个真阳性、5 个假阳性 |
| 文本 Recall | 0.750 | 6 个真阳性、2 个假阴性 |
| 文本 F1 | 0.632 | 不能据此声称生产可用 |
| 固定交易示例的规则自动匹配 | 3/3 对符合预先定义的真值 | 仅是 23 条虚构记录的功能检查 |

评估输出在 `docs/evaluation.json`。基础模型表现有限，所以所有模糊关联都需要人工复核。文本相似并不能证明是同一笔交易。没有真实公司试点或效率提升数据。

## 技术与项目结构

原生 HTML / CSS / JavaScript，无构建步骤；JSZip 3.10.1 已随项目附带，用于读取 XLSX 压缩包，许可在 `dist/vendor/JSZip-LICENSE.md`。其余业务代码无运行时依赖。

```
dist/
  index.html      界面
  app.js          导入、复核、撤销、报告与操作记录
  engine.js       金额、日期、验证、对账和导出
  model.js        标注数据、TF-IDF、模型训练和评估
  io.js           CSV 与有限 XLSX 解析
  demo.js         虚构交易及预先定义的匹配真值
  examples/       两张可下载示例 Excel
  vendor/         JSZip 及许可
tests/           自动检查、评估脚本和浏览器导入检查
docs/            评估、演示说明和申请项目学习材料
```

## 开发与复现

可选安装 Node.js 18 或更新版本。没有 npm 依赖，不需要 `npm install`。

```
npm test
npm run evaluate
npm run serve
```

访问 `http://127.0.0.1:8766`。浏览器文件导入测试页在 `http://127.0.0.1:8766/__qa`，验证实际 XLSX、两种日期存储、CSV 和导出安全。GitHub Actions 在提交与 PR 时运行核心测试。

## 数据格式与边界

- 各表最多 2,000 条交易、100 列，文件最大 15MB，解压体积最大 40MB。
- 第一版只支持一对一，币种 CNY/USD/EUR/GBP/HKD，各币种按两位小数处理。没有汇率换算。
- 收入正、支出负，或收入支出两列非负。会计借贷方向需要先转换为账户收支方向。
- 支持 YYYY-MM-DD / YYYY/MM/DD / 中文年月日、Excel 数字日期与 ISO 日期单元格。
- XLSX 公式仅读缓存值，须在 Excel 重算并保存；加密、旧 XLS 和复杂布局不支持。
- 交易编号最好以文本存储以保留前导零；标题行以下不要放合计或备注行。
- 无效行进入数据问题，不参与总额或匹配；报表因此可能不完整，须修正后重新导入。
- 未匹配列表包含尚未确认的候选；金额差异只建立关联，不生成调整分录。
- 刷新页面会清空所有数据和复核操作。程序不使用持久存储，也不修改源文件。
- 所有上传文件、训练、匹配和报告生成均在浏览器内完成；没有外部 AI 服务或遥测。
